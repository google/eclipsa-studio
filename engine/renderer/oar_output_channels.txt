# OAR output channel order and speaker geometry, one section per target
# layout, transcribed from the OAR fork's own table:
# src/renderer/olr/object_audio_renderer/layout.c (g_speaker_layouts).
#
# That table is not linkable from here — its Bazel package is visible only
# inside the oar repo — so this file is the one transcription of it, and
# both sides of the FFI pin against this file instead of against each
# other (ES-592):
#
#   engine/test/oar_output_channels_test.cc drives OAR's public render API
#     and asserts a source at each row's angles lands on that row's output
#     channel, so an OAR_COMMIT bump that reorders a layout or moves a
#     speaker fails at the layer that defines the order.
#   app/test/renderer/oar_output_channels_test.dart asserts SpeakerLayout
#     and OarLayout carry the same order, geometry and oar_layout_t values.
#
# Section header: [<layout id>] <oar_layout_t value>
# Channel row:    <OAR label> <app label> <azimuth> <elevation> <lfe|->
#
# The final [names] section is the glossary: one line per app label,
# `<app label> <full name...>`, the name a tooltip shows for that
# channel. It has no oar_layout_t value, and its rows run to the end of
# the line because a full name has spaces. It covers exactly the app
# labels the layout sections use.
#
# Azimuth is positive to the left, elevation positive up, both in degrees.
# Row order is the output channel order. Layout ids match SpeakerLayout.id
# in app/lib/renderer/speaker_layout.dart.
#
# The two label columns have different provenance. The OAR label is
# transcribed from the fork's table with everything else in the row, and
# the C++ test checks the row against OAR by rendering, not by name. The
# app label is Eclipsa Studio's own name for that channel -- what the
# meters, the routing matrix, the timeline and the 3D scene must all
# call it (ES-552) -- so OAR does not define it and the C++ test ignores
# it. Three Dart tables spell it out (SpeakerLayout.speakers[i].label,
# standardChannelLabel, iamfChannelLabels); before this column they were
# only checked against each other, so a rename could pass through all
# three. One deliberate exception is not pinned here: a 1-channel file
# reads "M" on the timeline, for DAW familiarity, where the scene's mono
# layout says "C".
#
# The full names in [names] are the tooltip copy in channelFullName
# (app/lib/waveform/multi_channel_waveform.dart), which is their only
# other home -- so unlike the columns above, this section adds a copy
# rather than replacing several. It earns that by making a channel's
# whole identity one line to read and one line to change, and by
# forcing every label a layout renders to have a name: without the
# coverage check a layout could use a label channelFullName has never
# heard of, and the tooltip would echo the short label back. Labels
# outside these ten layouts (7.1.5.4's Tc/Lbf/Rbf/Lbr/Rbr, the
# timeline's mono "M") stay in that function alone.
