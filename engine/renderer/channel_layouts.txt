# The key to every channel name and channel order Eclipsa Studio puts
# over the IAMF and OAR layer: one section per layout, transcribed from
# the OAR fork's own table, src/renderer/olr/object_audio_renderer/
# layout.c (g_speaker_layouts), with each channel's IAMF name and its
# short and long Eclipsa Studio labels.
#
# A layout has one or two roles, named on its header line. As a
# `monitoring` target, the rows are the order OAR renders the layout's
# output channels in. As an `element` layout, they are the order OAR
# takes a channel-based element's channels in. Both are the order an
# IAMF file stores the layout's channels in (the OAR/IAMF order).
#
# Columns: the OAR code is the fork's own name for the speaker. The IAMF
# name is iamf-tools' ChannelLabel string for the channel; the export
# writes the matching CHANNEL_LABEL_* enumerator, upper case with
# underscores and, for the 2-, 3-, 5- and 7-channel beds, a layout suffix
# (CENTRE for C, MONO for M, FLC for FLc, SI_L for SiL, TP_SI_L for TpSiL,
# LSS_7 for 7.1's Lss). The short label is what the UI shows for that
# channel: the meters, the routing matrices, the timeline lanes and the
# 3D scene. The long label is the name a tooltip shows for it. A short
# label has the same long label in every layout it appears in.
#
# The short labels differ from the IAMF names in these places:
#   mono: the 1-channel timeline lane reads M; the scene says C.
#   5.1.4 and 7.1.4: the top back pair Ltb/Rtb reads Ltr/Rtr.
#   7.1.5.4: TpC reads Tc, Ltb/Rtb read Ltr/Rtr, and the bottom layer
#     BtFL BtFR BtBL BtBR reads Lbf Rbf Lbr Rbr.
#   9.1.6: the familiar names of the other layouts (L R C LFE Lw Rw Lss
#     Rss Lrs Rrs Ltf Rtf Lts Rts Ltr Rtr) stand for the IAMF names
#     (FLc FRc FC LFE FL FR SiL SiR BL BR TpFL TpFR TpSiL TpSiR TpBL TpBR).
#     The UI adds the IAMF name in brackets where there is room.
#   10.2.9.3: the same familiar names as 9.1.6 for the channels it shares
#     with it, plus LFE for LFE1, Cs for BC, Ctf for TpFC, Tc for TpC,
#     Ctr for TpBC, Cbf for BtFC and Lbf/Rbf for BtFL/BtFR.
# The 7.1 family's side pair at +-90 degrees is Lss/Rss, as in IAMF; the
# 5.1 family's surround pair at +-110 degrees is Ls/Rs.
#
# The only reorder is 9.1.6. OAR renders it, and takes a 9.1.6 element,
# in Sound System H order (the [9.1.6] section). Eclipsa Studio's 9.1.6
# order is OBR's "IAMF 9.1.6 Alt" order (kLayout9_1_6_ch_alt in the oar
# module's obr/docs/loudspeaker_layouts.md), the [9.1.6-alt] section: the
# 9.1.6 monitoring target's output channels and a 9.1.6 element's
# channels. engine/renderer/channel_order.h holds the permutation and its
# inverse and the engine applies them at the OAR boundaries: the live
# monitoring output (AudioGraph::process), the element feed on the audio
# thread and in the offline render (OarRenderer::update_element_data).
# app/lib/models/layout_916.dart describes the same order for the app.
# IAMF export does not pass through OAR: it lists the channel labels per
# WAV channel. Every other layout, 10.2.9.3 included, is rendered, taken
# and shown in the OAR/IAMF order.
#
# Both sides pin against this file instead of against each other (ES-592):
#
#   engine/test/channel_layouts_test.cc drives OAR's public render API
#     and asserts a source at each row's angles lands on that row's output
#     channel, so an OAR_COMMIT bump that reorders a layout or moves a
#     speaker fails at the layer that defines the order. It also pins the
#     channel_order.h tables against the [9.1.6-alt] section, and checks
#     that every row has a long label and that a short label has one
#     long label. It reads OBR's virtual loudspeaker positions through
#     obr::ObrImpl and pins the binaural sections against them.
#   app/test/renderer/channel_layouts_test.dart asserts SpeakerLayout,
#     OarLayout, the element registration (elementToOarType),
#     standardChannelLabel, iamfChannelLabels, channelFullName and the
#     9.1.6 table in layout_916.dart carry the same order, names, geometry
#     and oar_layout_t values, and that SpeakerLayout's binaural geometry
#     is the binaural sections.
#
# Section header: [<layout id>] <oar_layout_t value> <role> [<role>]
#                 roles: monitoring, element
# Channel row:    <OAR code> <IAMF name> <short label>
#                 <azimuth> <elevation> <lfe|-> <long label...>
# Alt header:     [<layout id>-alt] <oar_layout_t value>
# Alt row:        <OAR code> <IAMF name> <short label> <long label...>
# Binaural header: [<layout id>-binaural] <oar_layout_t value>
# Binaural row:    <OAR code> <azimuth> <elevation>
#
# The long label runs to the end of the line because it has spaces. An
# alt section lists the layout's channels in Eclipsa Studio's order; each
# row names a row of the layout section by its OAR code and repeats that
# row's names. Only 9.1.6 has one.
#
# On the binaural monitoring target, OAR passes a channel-based element
# to OBR, which renders each channel from a virtual loudspeaker in its
# own table (obr/renderer/loudspeaker_layouts.h in the obr module)
# instead of at the angles of the layout section. OBR's upper layer is at
# elevation 45 where OLR's is at 30, 5.1.4's top pairs are at azimuth 45
# and 135 where OLR's are at 30 and 110, and the LFE is at azimuth 0 in
# every layout with an LFE but 9.1.6 and 10.2.9.3. A binaural section
# lists, in the layout section's order, the position OBR gives each
# channel of an element layout; the 3D scene draws a channel-based
# element there while the binaural target is monitored.
#
# An element whose headphones rendering mode is Stereo does not reach
# OBR: OAR renders it to stereo and outputs that unchanged on the
# binaural target, and the scene draws its sources inside the listener's
# head. A Binaural element registers as a stereo element. Creator pushes
# Stereo for every Binaural element in a sub-mix. A Binaural element
# therefore reaches OBR and takes the [stereo-binaural] rows only in
# Creator when no sub-mix pushes a mode, and in Playback when the file
# gives it a mode other than Stereo, or none.
#
# Azimuth is positive to the left, elevation positive up, both in degrees.
# Layout ids match SpeakerLayout.id in app/lib/renderer/speaker_layout.dart
# and, case aside, LoudspeakerLayout.displayName and OarLayout.label.
# Binaural renders through HRTFs, so the render test skips it. Its two
# rows are the stereo geometry, which the 3D scene gives a Binaural
# element's sources; on the binaural target the scene draws headphones.
#
# The OAR code is transcribed from the fork's table with the geometry,
# and the C++ test checks the row against OAR by rendering, not by name.
# OAR does not define the IAMF name or the labels, so the C++ test only
# checks that they are present and distinct within a layout; the Dart
# test pins the app's tables to them. One exception is not pinned here:
# a 1-channel file reads "M" on the timeline, where the scene's mono
# layout says "C".
