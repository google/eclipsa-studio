# Eclipsa Studio Releases

What's new in each version of Eclipsa Studio.

---

## 0.31.0 — October 29, 2026

- **New: Keyboard shortcuts for the workspace tabs.** Cmd+1, Cmd+2 and Cmd+3 (Ctrl+1, Ctrl+2 and Ctrl+3 on Windows) select the tabs in top bar order: Elements, Mix and Renderer in Creator, and Inspector and Renderer in Playback. The View menu lists each tab with its shortcut, and Help > Keyboard Shortcuts lists the shortcuts for the open workspace.
- **Changed: The output mix gain is set beside the layouts in the Mix view.** A knob and a value field labelled OUTPUT MIX GAIN, at the left of the LAYOUTS bar at the foot of the Mix view, set the gain applied to the mix of all elements in a mix presentation, from -60 to +12 dB, ahead of the layouts whose loudness it changes. The MASTER strip, with its fader and its meter, is removed. Its meter showed only the first two channels of the monitoring target; the output meter in the Renderer view shows every channel.
- **Improved: Out-of-date loudness figures are greyed out.** After a change to the session, such as a gain change, the integrated loudness and true peak on each layout in the Mix view are greyed out until the next measurement. In 0.30.0 they were drawn like current figures, and only the Re-measure Loudness button and the layout's tooltip said they were out of date. The export measures again before it writes them.
- **Changed: Base-Advanced requires object-based elements to have mix presentations of their own, listed first.** A Base-Advanced mix presentation that includes object-based elements must include only object-based elements, and when any mix presentation includes them, the first mix presentation must be one of these. For a Base-Advanced session that breaks either rule, the export dialog lists the error and does not export, Session Settings shows the Object mixes row as Not met with what to change, and opening the session offers a switch to Advanced-1. For a session on another profile that breaks either rule, the IAMF profile menu disables Base-Advanced and says why. Before, the export wrote these sessions as Base-Advanced; a decoder that checks the rules leaves out a mix presentation that breaks the first rule and rejects a file that breaks the second.
- **Fixed: Import ADM says when a WAV file has no ADM metadata.** A WAV file without ADM metadata, such as a 7.1.4 bed, passed the Import ADM dialog, and the import failed only after the profile, folder and session name had been entered and Import clicked. The dialog now says "This WAV file has no ADM metadata." in place of the preview, keeps Import disabled, and offers Open as Plain WAV, which starts a new session with the file as its first element, as dropping the file on the Creator card does.
- **Fixed: Playback that was paused and resumed returns to where it started.** With Return playhead on stop on, pressing Play after a pause made the pause point the position the playhead returned to. When playback then reached the end of the session or was stopped, the playhead went back to the pause point, and every later play from there did the same. A pause now keeps the position playback started from, and Return to start during playback sets that position to the start of the session.
- **Fixed: The video panel can no longer be dragged so tall that it squeezes the view below it.** Dragging the bottom edge of the video panel down made it up to 600 px tall at any window height, which squeezed the view below it. In a short window the bottom of the Mix view's channel strips was cut off. The video panel is now at most 600 px tall and at most half of the height between the top bar and the status bar, and it leaves at least 320 px for the view below it. It gets shorter when the window does, down to 100 px, and returns to the height it was dragged to when the window grows again.
- **Fixed: Element cards in Playback no longer include the output mix gain in their gain.** In the Renderer view in Playback, each element card showed its mix gain plus the output mix gain, which the line under the cards also shows: an element at -3 dB in a mix presentation at -6 dB read -9.0 dB. The cards now show the element's own mix gain. In Creator and Playback, the output mix gain line under the cards is drawn as the cards' gain lines are.
- **Fixed: Loudness on the 10.2.9.3 (22.2) layout uses the right signal on the Lss loudspeaker for scene elements.** When the Loudness Report or an export measured a mix presentation on the 10.2.9.3 layout, a scene element's Ltf signal was also rendered to the Lss loudspeaker, and the signal for Lss was left out. The loudness an export stores for that layout changes for mix presentations with a scene element.
- **Fixed: Names that are not valid UTF-8 no longer stop a file or the output device list from loading.** An IAMF or MP4 file whose mix presentation name or language is not valid UTF-8 did not open in Playback, and no message said why. On Windows, a device driver name in the system code page with characters outside ASCII made the output device list fail to load. Characters that cannot be read now show as �.
- **Fixed: Selected rows in the Loudness Report are drawn apart.** Two rows selected next to each other to show their traces met edge to edge, with a dark line between their fills; the IAMF or MON tag at the right end of a selected row touched the edge of its fill; and the hover highlight had square corners under the rounded fill. Rows are now 2 px apart, the tag sits 8 px inside the fill, and the highlight has rounded corners, in the Loudness Report in Creator and in Playback.
- **Improved: The borders that resize the video panel and the track panels are 1 px thick.** The border under the video panel and the divider between the track panels and the waveforms in the Elements view were 0.5 px thick, half as thick as the other panel borders. Both are now 1 px in every theme, and so is the border under the collapsed video panel in the Classic and High Contrast themes.
- **Changed: Release Notes is listed once in the macOS menus.** It was in both the Eclipsa Studio menu and the Help menu, and is now in the Help menu only, as on Windows.
- **For developers:** The engine builds OAR at `a7a5cc89` from AOMediaCodec/oar, which merged the fork's allocation-free rendering, object position timeline after paused renders and binaural renderer changes in AOMediaCodec/oar#52, AOMediaCodec/oar#54, AOMediaCodec/oar#55, AOMediaCodec/oar#56 and AOMediaCodec/oar#58; the 10.2.9.3 fix is AOMediaCodec/oar#49. `engine/deps/oar/oar.patch` carries the changes upstream does not have: `oar_get_limiter_env()`, the layout-anchored position conversion and its helpers, the threading contract in `oar.h`, the OLR azimuth wrapping and EAR dangling-pointer fixes, OLR's interpolated-gain loop, and the group and element gain passes skipped when no gain metadata is queued. `obr.patch` carries no changes. The engine builds iamf-tools at `a4f98a5d` (module version 3.0.0), which takes Opus and FLAC from the Bazel Central Registry in place of pinned git checkouts: Opus moves from 1.5.2 to 1.6.1, and FLAC from 1.5.0 plus 3 commits to 1.5.0. `engine/deps/iamf_tools/iamf_tools.patch` no longer carries `probe_json.cc` and `read_bit_buffer.cc`, whose fork changes upstream merged in AOMediaCodec/iamf-tools#107, AOMediaCodec/iamf-tools#108 and AOMediaCodec/iamf-tools#110. `eclipsa_studio_cli measure` prints `limiter=on` or `limiter=off` and `limiter_gr_max_db`, the limiter's largest gain reduction, for IAMF input. For IAMF input it writes the 100 ms momentary, short-term, short-term peak and limiter gain reduction traces as JSON with `--trace-json`, and the measured render as a 32-bit float WAV with `--render-wav`. `--no-limiter` measures IAMF or WAV input with the -1 dBFS limiter off; the app has no such switch, and monitoring, the Loudness Report and the export's loudness measurement stay limited. A value flag followed by another flag, such as `--render-wav --no-limiter`, is now a usage error. `scripts/collect_third_party_notices.py` takes `--no-aac`, `--no-flac` and `--no-opus`, which leave out the AAC, FLAC and Opus notices for a build without that codec. The generated Flutter plugin registrant files are no longer tracked; `flutter pub get`, which the build scripts and CI run before every build, writes them.

## 0.30.0 — October 20, 2026

- **New: Solo and mute for each output channel.** In the Monitoring panel of the Renderer view, hovering a channel label of the output meter opens a panel with the channel's full name, such as Lw (FL) at 9.1.6, and its S and M buttons. A muted channel is silenced, and while any channel is soloed every channel that is not soloed is silenced. A silenced channel fades out over 15 ms, its meter label turns yellow when soloed and red when muted, and the 3D scene fades its loudspeaker or earcup. While a channel is soloed or muted, the status bar shows OUT SOLO or OUT MUTE in every view, and a click on it clears both. Solo and mute change only what is monitored: the meters, the Loudness Report and exports are unaffected. They clear when the monitoring target changes and are not saved.
- **Improved: The 3D scene draws the monitoring target and the element sources separately.** A loudspeaker target is drawn as its loudspeakers, labelled as on the output meter and lit by the output levels. The binaural target is drawn as headphones, with each earcup lit by its output level. Each channel of a channel-based element is a sphere in the element's colour at the position it is rendered from: its loudspeaker position, or on the binaural target the virtual loudspeaker the binaural renderer uses, which places the height channels at 45 degrees elevation instead of 30. An element played as stereo on headphones is drawn as two sources inside the head. Muted elements, and elements silenced by another element's solo, fade towards the background. Before, every channel of a channel-based element was drawn as an unlabelled loudspeaker at its layout position on every target.
- **Improved: ADM import is faster and uses less memory.** Importing a 54-track, 337 s master took 29.1 s on a computer with 18 cores and now takes 5.4 s, and its peak memory fell from 6.7 GiB to 1.2 GiB. The master is read in chunks while it renders on up to 8 threads, so the import progress starts to move after 0.28 s instead of 4.7 s. The bed WAV it writes is the same byte for byte. Reading ADM metadata with 60,000 track UIDs or 80,000 audioContent entries took 19.2 s and 71.3 s and now takes 178 ms or less.
- **Improved: Playback no longer allocates memory or reads files while it renders.** Rendering for monitoring made up to 8317 memory allocations per 512-frame block on the binaural target, and 4 for a bed or a scene on loudspeakers, and now makes none. WAV elements are read on a separate thread that keeps 32768 frames (682 ms at 48 kHz) of each element buffered; before, every audio block read the file, so a slow disk or a network volume interrupted the output. When the disk falls further behind than that buffer, the element goes silent and comes back in step with the playhead 170 ms or more later, with a fade-in. The live loudness meter runs on its own thread, where its work grew with playback time.
- **Improved: Binaural monitoring uses less processing time.** Rendering eight object elements to the binaural target took 0.247 ms per 512-frame block and now takes 0.134 ms. A 7.1.4 bed, a third-order scene and two object elements together took 0.34 ms and now take 0.145 ms.
- **Fixed: Object elements no longer use more memory the longer playback runs.** On a loudspeaker monitoring target, each object element kept every position update it received, about 94 a second at 48 kHz. Eight object elements on 7.1.4 for about 18 minutes peaked at 65.7 MB and now peak at 8.3 MB.
- **Fixed: Object elements stay audible after playback is paused.** On a loudspeaker monitoring target, an object element went silent after a pause and stayed silent until the monitoring target was switched or an element was added or removed.
- **Fixed: On the binaural target, head-locked elements no longer move world-locked elements.** In a mix with elements in both the Binaural World-locked and the Binaural Head-locked headphones rendering modes, channels were rendered from the positions of other channels: a world-locked object at -90 degrees, on the right, was heard on the left beside a head-locked object at +90 degrees.
- **Fixed: Switching the mix presentation during playback no longer clicks.** The renderer is rebuilt on a switch of monitoring target, on a change to an element's headphones rendering mode or binaural profile, which a mix presentation switch can make, and when an element is added, removed or changes format. After each rebuild during playback the sound came back in with a step, and it now fades in over 10 ms. In Playback, a mix presentation switch no longer cuts the output when the monitoring target stays the same. A change to an element's input routing during playback no longer silences the element for one audio block.
- **Fixed: A WAV element added during playback plays in step with the session.** It started at the beginning of its file, out of step with the other elements by the playhead position, as did an element whose WAV was replaced during playback. It now starts at the playhead position 170 ms or more after it is added, and fades in.
- **Fixed: Monitoring settings are saved for the output device they were made on.** An edit to the output targets, their routing or the output channel labels replaced another device's saved settings when it was made right after a switch of output device, after the device failed to reopen, or with System Default selected after the device list changed. An edit made before a device's settings had loaded wrote the built-in defaults over them and is no longer saved.
- **Fixed: Picking the active mix presentation again keeps its sub-mix.** Picking the mix presentation that was already active, in the top bar or on its tab in the Mix view, switched to its first sub-mix and, during playback, rebuilt the renderer.
- **Improved: The scrub bar stays in the top bar on the Elements tab.** It was hidden on the Elements tab and is now shown on every tab in Creator and Playback.
- **Improved: The mix presentation menu in the top bar works with the keyboard.** It takes keyboard focus, opens with Enter or the arrow keys, and is announced as "Mix presentation" by screen readers. It matches the other drop-down menus: the selected presentation is marked by the accent colour instead of a check mark. With no mix presentations it reads "No mix presentations" and is disabled.
- **Fixed: Drop-down menus show the focus ring only after a key press.** After a click, a drop-down menu drew the keyboard focus ring while it was open and after it closed, and kept focus, so the arrow keys opened it again. A menu used with the mouse now gives up focus when it closes. Tab, Enter, Space and the arrow keys work as before.
- **Changed: New glyphs for the element types.** Object elements are drawn as a source on an orbit, scene elements as four first-order lobes and channel elements as a single loudspeaker, in the Mix channel strips, the Renderer element cards, the Elements view, and the Choose Element Format and Type & Routing windows. The type line on the Mix and Renderer cards shows the glyph in the type colour and the type and layout in the secondary text colour, without the tinted background. In the Elements view, the type control under an element's name is drawn like the other drop-down controls, and the drag handle shows the same three-bar glyph for every type. The handle, the lane and the file details on the lane are drawn in the type colour of the active theme, as the waveform is; after a theme switch they kept the colour of the theme the element was added in. The dot before an element's name in the Mix view's Add Element menu uses the type colour too, and so do a channel-based element's sources in the 3D scene, the Transient wavefronts, Correlation ribbons and Intensity vector visualizers, and the dot before the element's name in the stats HUD.
- **Improved: Renderer element cards are one height.** An object's position reads on one line, such as Az 30.0° El 0.0° Dist 1.00, with each value in a slot as wide as its widest value, so the labels stay in place as the values change. A dual object's Spread moves to the position tooltip. Channel and scene cards keep an empty position line and an element outside the mix presentation keeps an empty gain line, so every card has the same height. The headphones line uses the full width of the card. At the Medium font size the lines are 12 px with 15 px glyphs and the numbers 11 px, where they were 10 px. The coloured dot before the element name is removed from the Renderer and Mix cards. An element outside the mix presentation shows a yellow "Not in mix presentation" line in place of the headphones line, with its glyph and label at the size of the other lines, where it showed a NOT IN MIX tag; the Elements view shows the same line above the element's meter.
- **Improved: The Mix channel strip shows the full element name and type in tooltips.** Hovering a name that does not fit the strip shows the full name, and hovering the type line shows the full type and layout.
- **Improved: The monitoring buttons, mix presentation tabs and layout chips share one drawing.** The Renderer view's monitoring target buttons and the Mix view's mix presentation tabs, layout chips in the LAYOUTS bar and two add buttons are drawn alike in each theme. The selected monitoring target and the active mix presentation tab are a solid fill in the theme's accent colour without an outline, with the name in semibold text in the colours of a dialog's confirming button; in Dark and Classic the selected target was a dim fill, in Dark with an outline. The other monitoring buttons and tabs, the two add buttons and the tagged layouts take the theme's button face, where the Mix view's tabs and chips were drawn the same in every theme. A layout's loudness figures are in the chip's text colour; a report the session has changed since is shown by the Re-measure Loudness button, where its figures were dimmed. The tabs and the add buttons take keyboard focus and Enter activates them, screen readers announce them as buttons and the active tab as selected, and the add buttons show tooltips. At the Medium font size tabs and layout chips are 24 px tall, where they were 26 px and 22 px. The NAME, LANG, LAYOUTS and MASTER labels use the style of the Renderer view's panel headers: semibold capitals, 12 px at the Medium font size.
- **Improved: The small tags are drawn alike.** The LIVE, MOMENTARY, SHORT-TERM and TRUE PEAK labels of the loudness readouts at the bottom of the Renderer view, EXPERIMENTAL on the Visualizers panel, SELECTED in the Playback inspector, IAMF and MON in the Loudness Report, and the Most common, Coming soon and video platform support tags use one size and shape: semibold text with 0.5 px letter spacing, 10 px at the Medium font size, on a rounded fill. A coloured tag is filled with its colour at 12%; LIVE keeps its highlighted fill, and the other loudness labels and Coming soon a grey one; SELECTED, IAMF and MON draw a 1 px outline in their colour and no fill. SELECTED, IAMF and MON were 8 px. The Loudness Report window is up to 1120 px wide, where it was 1100 px, to keep its columns on one line at the Large font size.
- **Fixed: A dual object element no longer hides another object element in the 3D scene.** A dual object and a single object could be drawn as one sphere, so one of them was missing from the scene.
- **Fixed: Replacing an element's WAV keeps the element's settings.** After a WAV with the same channel count replaced an element's file, or a WAV was assigned to an element whose file was missing, the element played with the default input routing, object position, mix gain and headphones settings until the mix settings were sent again, for example by a switch of mix presentation. A replacement with a different channel count now removes the old element's settings from every mix and is checked against the IAMF profile's channel, element type and layout limits before the old element is removed.
- **Fixed: Changing an element's type keeps its headphones rendering mode and binaural profile.** After a type change the element was rendered as Binaural World-locked with the Ambient profile until the mix settings were sent again.
- **Fixed: Meters follow their element after the elements are reordered.** A Mix view channel strip, a Renderer element card and the element's sources in the 3D scene could show the levels of another element.
- **Fixed: Deleting the active mix presentation in first place updates the audio.** The renderer kept the deleted mix presentation's settings until another mix presentation was picked.
- **Fixed: A change confirmed after another session was opened no longer changes that session.** A WAV replacement or import, a mix presentation deletion or a Type & Routing change confirmed after another session was opened was applied to the new session. It is now dropped, with a notice for an import.
- **Fixed: The shading past the end of a track follows a theme switch.**
- **For developers:** `engine/renderer/sync-oar.sh` and `engine/iamf/sync-iamf-tools.sh` take `--keep-pin`, which regenerates the patches against the pin in `engine/MODULE.bazel` and leaves the pin unchanged, and write a patch only after `git diff` succeeds. The engine still builds OAR at `3fea539e`; `engine/deps/oar/oar.patch` and `obr.patch` carry the fork changes for allocation-free rendering, the object position timeline after paused renders, one binaural encoder each for the head-locked and world-locked passes, and head rotation set through atomics. `//renderer:oar_render_bench` times the per-block render on stereo, 7.1.4 and binaural and counts heap allocations per block in `--config=asan` and `--config=tsan` builds; `//adm_import/convert:adm_import_bench` times an ADM import, its first progress report and its peak memory. `oar_render_alloc_test`, `live_loudness_meter_test` and `wav_stream_test` require no heap allocation on the audio thread. Data races on the element gain targets, the output channel count, the meter element count and per-element input routing, found with ThreadSanitizer, are fixed. `eclipsa_studio_playback_open` removes the previous session's elements from the renderer when it fails or opens over an attached session. The engine exports `eclipsa_studio_set_output_solo_mute()`, and `ECLIPSA_STUDIO_ENGINE_API_VERSION` is 20261019.

## 0.29.0 — October 1, 2026

- **New: Loudness Report for an IAMF file.** In Playback mode, View > Loudness Report measures the open file at every loudness layout it declares and at the monitoring layout, and shows the measured integrated loudness, true peak, digital peak, loudness range and limiter gain reduction beside the values stored in the file, with the difference in integrated loudness. Nothing is written to the file.
- **Improved: Large IAMF files open in under a second.** An 11.8 GB IAMF file took 564 s to open on a computer with 16 GB of memory and now opens in 103 ms. An 11.7 GB MP4 with an IAMF track had not opened after 9.5 minutes and now opens in 226 ms.
- **Improved: IAMF files with LPCM audio decode faster.** Measuring one layout of a 21-minute 12-channel LPCM file takes 6 s instead of 24 s at stereo, in Playback and in the Loudness Report.
- **Fixed: Playback of an IAMF file starts while its duration is still being read.** Play stayed silent until the duration scan finished, about 19 s for an 11.8 GB file. A seek to the exact end of the file reported an error and now stops at the end.
- **Changed: 9.1.6 monitoring and 9.1.6 elements use one channel order.** Output channels 1 to 16 carry L30 R30 C LFE L60 R60 L90 R90 L135 R135, then the top front, side and back pairs, and a 9.1.6 element's WAV is read in the same order. The labels read L R C LFE Lw Rw Lss Rss Lrs Rrs Ltf Rtf Lts Rts Ltr Rtr, with the IAMF channel name in brackets where there is room. A WAV in the IAMF bitstream order needs its channels reordered first. A saved 9.1.6 output routing loads as it was saved, so check it against the new order.
- **Changed: The 7.1 side speakers are labelled Lss and Rss.** The 7.1, 7.1.2 and 7.1.4 layouts labelled the pair at 90 degrees Ls and Rs. The 5.1 layouts keep Ls and Rs. Exported files are unchanged.
- **Fixed: 7.1.5.4 and 10.2.9.3 elements play all their channels.** A 7.1.5.4 element lost its 17th channel and a 10.2.9.3 element played as stereo. The 3D scene draws both layouts, and their Mix view strips keep their width when levels arrive.
- **Improved: The Renderer view's output targets use the theme's buttons.** They fill the panel in rows of equal buttons. A target with more channels than the output device is dimmed and cannot be selected.
- **Fixed: Switches are visible in every theme.** An off switch looked like an empty box in the Dark, Classic and High Contrast themes. The on knob was cut off at its right edge and its glow spread outside the track.
- **Fixed: In the High Contrast theme, switches and segmented controls draw the same 2 px rim as drop-down menus.** A disabled segmented control drew its rim in two tones and now draws it in one.
- **Fixed: The output meter frame has rounded corners in every theme.**
- **Fixed: Long tooltips wrap at 360 px.** A long tooltip ran as one line across the window.
- **Fixed: The transport controls stay in place as the clock changes.** The scrub bar, the transport buttons and the mix selector moved when the position passed one hour and when the duration scan finished.
- **Fixed: The landing screen stays in place as the Recent lists change length.** The "Authoring for" caption in the Light theme is darker and reads at a contrast of 4.5:1 or more.
- **Fixed: An output label being edited is no longer saved to another device.** When the system default output device changed or the selected device was removed while the routing matrix was open, the label being edited replaced the new device's label.
- **Fixed: A session keeps its own video path when its video fails to load.** Opening a session whose video was missing left the previous session's video loaded, and saving wrote that video's path into the session. The video panel has a button that removes the missing video from the session.
- **Fixed: The video pop-out follows theme and font size changes after its file fails to load.** Its time readout is centred under the picture.
- **Fixed: The Transient wavefronts module keeps working after an element gains channels.** Changing an 8-channel element from Stereo to 5.1 made the Renderer view report an error on every frame.
- **For developers:** `eclipsa_studio_cli measure <file> --layout <name>` measures a mix WAV or an IAMF file (`measure-iamf` is the old name) and takes `--channel-order alt|iamf` for a 9.1.6 WAV. `probe` and `measure` take an MP4 with an IAMF track, `encode --out <file.iamf|file.mp4> [--video V]` writes either container, `bounce` rejects an output that is its input, and every command takes `--help` and prints the engine's reason for a failure. The app takes `--open <file>`, `--playback` (old name `--iamf`), `--quit-after-load` and `--help`; `./build.sh run --open FILE`, `test-session` and `test-playback` pass them. The engine builds against iamf-tools commit `e101eac7`, and the export no longer writes the textproto fields iamf-tools 3.0.0 deprecates.
